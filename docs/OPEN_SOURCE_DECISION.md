# 开源基座选型记录

## 决策

使用 Vikunja 稳定发行版作为任务核心，在企业 fork 中开发独立的零售扩展模块。

决策日期：2026-08-21。

## 业务侧权重

| 评估项 | 权重 | 说明 |
|---|---:|---|
| 高频/重复待办 | 20% | 开闭店、清洁、陈列、盘点等 |
| 手机端执行效率 | 15% | 店员主要在卖场操作 |
| 提醒与截止时间 | 15% | 降低遗忘和催办成本 |
| 人员与门店权限 | 15% | 防止跨门店越权 |
| 完成凭证与复核 | 15% | 照片、说明、返工闭环 |
| 自托管和运维 | 10% | 数据可控、可备份、可升级 |
| 二开复杂度 | 10% | 小团队可维护 |

## 候选比较

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| [Vikunja](https://github.com/go-vikunja/vikunja) | 任务导向；重复、提醒、附件、关系和团队共享；部署轻 | 企业审计、工时等部分能力不在开源核心；组织模型需扩展 | 首选，但生产前必须完成许可评估 |
| [Plane](https://github.com/makeplane/plane) | 现代界面；研发项目、周期、模块和分析优秀 | 产品概念偏研发；零售重复任务和复核流程需较多改造；组件更多 | 若未来以产品研发为主再考虑 |
| [OpenProject](https://github.com/opf/openproject) | 权限、甘特图、工时、成本和项目组合成熟 | 对门店每日待办过重；培训和运维成本较高 | 适合工程型项目，不作为首版 |
| [Leantime](https://github.com/Leantime/leantime) | 目标、任务、日历、甘特图、权限和 LDAP/OIDC 较完整 | PHP 技术栈与预期扩展团队匹配度待确认 | 备选 |
| [Wekan](https://github.com/wekan/wekan) | MIT；看板简单，部署快 | 复杂工作流、分析、领域扩展能力有限 | 可用于低成本临时方案 |

## 二开原则

1. 固定上游稳定版本，禁止生产环境直接跟随 `main`。
2. 原有任务、用户、附件、提醒能力优先复用，不复制一套平行核心。
3. 新增代码使用 `retail` 领域命名，数据库采用新增表和可回滚迁移。
4. 对上游核心的修改保持最小；可通过事件、服务层或组件插槽完成时，不直接改核心逻辑。
5. 每月检查上游安全修复，单独建立同步分支并执行完整回归。
6. 保留上游版权、许可证和源码入口；企业品牌不得暗示与 Vikunja 官方存在授权关系。
7. 不移除、绕过或复制 Vikunja 的许可证检查；许可功能通过采购获得，或重新选型。

## 退出条件

出现以下任一情况时重新评估基座：

- 关键需求要求修改超过三个上游核心领域且无法隔离。
- 连续两个稳定版本无法安全同步上游安全修复。
- 移动端执行关键流程经过两轮优化仍无法达到可用性指标。
- AGPL 合规策略无法得到企业确认。
- 实际规模超过 2,000 活跃用户且性能验证不通过。
