# 寝务看板 PRD

版本：0.2 MVP 上线候选
状态：已完成开发基线，待真实门店 UAT 签字
负责人：零售运营负责人（待指定）

## 1. 背景

床上用品零售门店存在大量跨时段、跨岗位且需要现场确认的事项，例如开店检查、样床陈列、价格标签、清洁、库存盘点、顾客回访、订单交付和售后处理。当前任务往往分散在口头、微信群和纸张中，总部、店长和员工看到的信息不一致。

本产品建立一条统一闭环：

> 标准模板 → 合理派工 → 员工执行 → 提交凭证 → 负责人复核 → 逾期升级 → 统计改进

## 2. 用户与职责

| 角色 | 主要职责 | 默认数据范围 |
|---|---|---|
| 系统管理员 | 账号、角色、基础配置、系统维护 | 全公司，不默认查看业务详情 |
| 总部运营 | 制定模板、跨店派发、查看经营执行数据 | 全公司或授权区域 |
| 区域经理 | 监督辖区门店、处理升级事项 | 所属区域 |
| 店长 | 安排本店人员、复核、处理逾期 | 所属门店 |
| 店员 | 查看和执行本人任务、协作任务 | 本人及被共享任务 |
| 仓库/售后 | 处理配送、库存、售后任务 | 所属组织单元 |
| 审计只读 | 查看记录和导出 | 明确授权范围 |

角色与岗位分开：岗位描述业务身份，角色决定系统权限。一个人可以同时拥有多个作用域角色。

## 3. 核心业务场景

### 3.1 每日开店与闭店

- 总部创建开店/闭店模板，包括清洁、灯光、样床、价签、收银和安全检查。
- 系统按照门店营业日自动生成任务。
- 店长在人员负荷视图中调整负责人。
- 员工逐项勾选，指定项目必须上传照片。
- 需要复核的任务进入店长待复核列表。

### 3.2 陈列与促销执行

- 总部向指定门店批量派发促销陈列任务。
- 任务携带陈列说明、示例图、开始/结束时间和验收清单。
- 门店上传完成照片，总部运营可抽检并驳回。
- 看板显示未开始、进行中、待复核、返工和已完成门店。

### 3.3 顾客跟进

- 店员创建顾客跟进任务，可选填外部顾客/订单编号，不在任务标题中保存手机号等敏感信息。
- 支持“2 小时、24 小时、3 天”等后续节点。
- 记录跟进结果和下次动作；首版不替代 CRM。

### 3.4 盘点与库存异常

- 按周或按月生成盘点任务。
- 清单记录待盘区域；差异通过附件和说明提交。
- 重大差异自动升级店长和区域经理。
- 首版仅跟踪处理过程，不计算 ERP 库存账。

### 3.5 配送和售后异常

- 创建异常任务，记录订单号、问题类型、严重程度和期望解决时间。
- 可以转交仓库或售后协作，但保留门店发起人和责任链。
- 关闭前要求填写处理结果；重要事项由发起门店确认。

## 4. 功能需求

### FR-01 组织和成员

- 支持公司、区域、门店、仓库四类组织单元。
- 成员包含姓名、工号、岗位、所属单元、直属负责人、状态和每日默认容量。
- 支持临时借调的开始、结束日期，不改变人员永久归属。
- 离职或停用账号不能登录，历史任务仍保留姓名快照。

### FR-02 任务模型

任务在 Vikunja 原有字段上增加：

- 归属门店/组织单元。
- 业务类别：开店、闭店、清洁、陈列、库存、销售跟进、配送、售后、培训、其他。
- 主负责人、协作人、复核人。
- 计划开始时间、截止时间、预计工时分钟。
- 验收清单、是否必须上传凭证、最低凭证数量。
- 来源：手工、模板、重复规则、外部系统。
- 外部单号，可存订单或 CRM 的非敏感标识。
- 严重程度和逾期策略。

每项任务只有一个主负责人。多人协作通过协作人和子任务表达，避免责任不清。

### FR-03 状态流转

标准状态：

`草稿 → 已分派 → 进行中 → 待复核 → 已完成`

异常分支：

- 待复核 → 已驳回 → 进行中。
- 草稿/已分派/进行中 → 已取消，需要原因。
- 无需复核的任务可从进行中直接完成。

规则：

- 员工只能启动、提交自己负责的任务。
- 复核人不能在缺少必填凭证时通过。
- 驳回必须填写原因，并保留每次提交版本。
- 完成后修改核心字段需要店长或更高权限，并写入审计日志。

### FR-04 任务模板与批量派发

- 模板包括标题、类别、说明、清单、预计工时、凭证规则、默认岗位、复核角色和逾期策略。
- 支持每天、每周、每月及指定星期的重复规则。
- 支持选择区域/门店批量派发。
- 生成任务时保存模板版本快照；修改模板不追溯改变已生成任务。
- 批量派发前展示预计任务数和无人可分配的门店。

### FR-05 我的今日待办

店员首页按以下顺序显示：

1. 已逾期。
2. 今天截止。
3. 进行中。
4. 后续待办。

移动端完成任务不超过四个主要动作：打开任务、勾选清单、上传凭证、提交。

### FR-06 人员负荷和派工

- 展示人员按天的可用容量、已分配分钟数和剩余分钟数。
- 负荷低于 80% 显示正常，80%—100% 提醒，超过 100% 警告；阈值可配置。
- 支持拖动或批量调整负责人和日期。
- 请假、借调和非工作日使当天容量减少或归零。
- 系统只给出分配建议，店长保留最终决定权。

首版不做自动排班算法；先保证容量数据和任务预计工时可信。

### FR-07 凭证与复核

- 凭证支持图片、文档和文字说明。
- 图片上传时压缩展示副本，保留必要的原始文件或合规归档版本。
- 复核列表显示任务要求、最新提交、历史驳回和截止时间。
- 通过或驳回记录操作者、时间、意见和提交版本。
- 凭证文件使用鉴权 URL，不允许匿名公开访问。

### FR-08 提醒与升级

默认规则：

- 截止前 30 分钟提醒主负责人。
- 到期未完成再次提醒主负责人。
- 逾期 2 小时通知店长。
- 逾期 24 小时通知区域经理。

站内通知必须首版完成。邮件和企业微信按配置启用，并保证同一事件不会重复轰炸。

### FR-09 看板与报表

管理看板至少包含：

- 今日任务总数、完成数、待复核数、逾期数。
- 按时完成率、逾期率、驳回率和平均完成时长。
- 门店、业务类别、人员和日期筛选。
- 人员未来七天负荷。
- 逾期任务清单和责任链。

报表口径：

- 按时完成：首次进入“待复核”或无需复核任务完成的时间不晚于截止时间。
- 驳回率：发生过至少一次驳回的任务数 ÷ 已提交复核任务数。
- 完成率：已完成任务数 ÷ 到统计截止时间应完成的有效任务数；已取消不计分母。

### FR-10 搜索与导出

- 支持按编号、标题、外部单号、标签和负责人搜索。
- 管理者可导出授权范围内的任务明细 CSV。
- 导出操作进入审计日志；包含顾客或订单标识的导出需要额外权限。

### FR-11 业务历史与合规审计

零售扩展必须记录任务派工、每次提交、复核和驳回等业务历史，这些记录是业务流程本身的一部分。

登录、授权、组织/角色变更、导出和管理配置变更等通用合规审计复用获得许可的 Vikunja 审计能力，不自行绕过或复制其许可证系统。生产上线门禁必须包含许可证采购或经书面批准的基座重评估。

## 5. 权限规则

- 默认拒绝：未显式授权时不可读取或修改。
- 店员不能浏览全店人员绩效，只能看到本人和任务协作所需信息。
- 店长只能管理所属门店；跨店借调人员仅在借调期和指定任务内可见。
- 区域经理只能查看辖区；总部权限也应按区域授权，而非自动全公司。
- 附件、评论、导出必须执行与任务相同或更严格的数据范围检查。
- 系统管理员负责技术配置，不自动获得敏感业务数据阅读权。

权限矩阵和接口级检查在技术设计中维护。

## 6. 非功能需求

### 可用性

- 试点期月度可用性目标 99.5%，正式运行目标 99.9%。
- 手机端首屏在普通 4G 网络下目标 3 秒内可操作。
- 关键按钮和状态使用文字加颜色，不能只靠颜色区分。

### 性能

- 500 用户、100 并发、100 万历史任务的目标规模下，常用列表接口 P95 小于 800ms。
- 看板聚合接口 P95 小于 2 秒；大范围导出异步生成。

### 安全

- 全站 HTTPS，密码使用上游安全哈希方案。
- 登录、复核和导出接口限流。
- 文件类型、大小和内容进行校验；禁止直接执行上传文件。
- 生产密钥不进入 Git 仓库。
- 高危依赖漏洞在 72 小时内评估和处置。

### 数据与恢复

- 生产数据库每日全量备份，关键文件每日备份。
- 目标 RPO 24 小时，RTO 4 小时；正式上线后再根据业务损失评估提升。
- 每季度执行一次恢复演练，不能只验证“备份任务成功”。

## 7. MVP 实现基线（2026-08-21）

已完成可部署的核心闭环：组织与人员权限、任务扩展属性、验收清单和凭证、提交/复核/驳回/重提历史、不可变模板版本、幂等批量派发、日/周/月自动计划、人员单日容量与负荷、站内超期升级、运营指标、中文响应式操作页面，以及 Docker/Caddy/PostgreSQL 部署和备份恢复脚本。

下列项目不阻塞当前单机试点，但在对应场景进入生产前需完成评审：

- 多节点高可用与 S3 对象存储。
- 企业微信通知、邮件升级和节假日日历。
- CSV 批量导入/导出、拖动改派和自动排班建议。
- 大规模性能验证、真实云环境恢复演练和真实门店 UAT。
- 通用合规审计的 Vikunja 商业许可证采购或经批准的基座重评估。

## 7. 首版不包含

- 员工工资、绩效奖金自动计算。
- 指纹、人脸、GPS 考勤。
- 完整班次排班和劳动法规校验。
- POS、ERP 或 CRM 的双向实时同步。
- AI 自动评价员工、自动处罚或自动调岗。
- 面向消费者的账号和商城功能。

## 8. 验收场景

1. 总部模板能向三家门店生成各自任务，且模板修改不影响已生成任务。
2. 店长看到本店每个人明日容量，超负荷分配时收到明确警告。
3. 店员手机端完成带三项清单和两张必需照片的任务。
4. 店长驳回后，员工收到原因并可再次提交；历史提交不可丢失。
5. 逾期两小时任务只通知对应店长，不泄露给其他门店。
6. 区域经理能按门店查看按时完成率，数字与任务明细一致。
7. 停用员工无法登录，但历史任务和审计记录可查询。
8. 从备份恢复到独立环境后，可以登录并查看恢复点之前的任务及附件。

## 9. 待业务确认问题

以下问题在需求阶段第 1 周确认，不阻挡文档和技术底座准备：

- 门店、区域、仓库的真实数量及未来两年增长预估。
- 现有岗位、上下级关系和借调方式。
- 五类最高频任务的纸质或微信群样例。
- 哪些任务必须拍照，照片需要保存多久。
- 企业微信、自有 ERP/POS/CRM 的系统名称和接口条件。
- 总部是否需要跨店排名，以及排名数据的管理用途。
- 生产部署地区、域名、备案、预算和运维负责人。
