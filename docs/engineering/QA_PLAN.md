# 测试与验收计划

## 1. 测试层次

- 单元测试：状态机、权限判定、指标口径、重复生成和升级规则。
- 集成测试：API、PostgreSQL、对象存储、邮件/企业微信适配器。
- 组件测试：任务表单、凭证上传、复核和负荷视图。
- 端到端测试：真实角色完成完整业务流程。
- 非功能测试：性能、安全、兼容性、备份恢复和可访问性。

## 2. P0 自动化用例

### 权限

1. 门店 A 店员读取门店 B 任务返回 403 或不可见结果。
2. 门店 A 店长不能把任务分配给无借调关系的门店 B 员工。
3. 区域经理只能读取所属区域。
4. 停用用户的令牌立即或在规定时间内失效。
5. 未授权用户不能通过附件 URL 绕过任务权限。

### 状态与复核

1. 草稿不能直接进入待复核。
2. 缺少必填清单或照片时不能提交。
3. 驳回必须有原因，并能再次提交。
4. 并发复核只能产生一个有效最终结果。
5. 已完成任务的受控修改产生审计事件。

当前自动化覆盖：店员开始任务、必填清单拦截、任务附件凭证归属校验、提交、复核越权拒绝、驳回原因、重新提交、通过同步底层任务完成状态，以及完整 API 链路。并发复核竞态测试仍列为上线前必补项。

### 重复和通知

1. 同一模板、门店和计划时间重复执行生成器不会创建两次。
2. 取消的模板不再生成未来任务。
3. 逾期升级只发给正确作用域管理者。
4. 通知失败可重试但不重复发送成功消息。

### 指标

1. 取消任务不进入完成率分母。
2. 首次按时提交、后来被驳回的任务按文档口径统计。
3. 跨时区边界使用 Asia/Shanghai 计算营业日。

当前自动化覆盖：模板旧版不可变、无权派发拒绝、派发幂等复用、清单快照复制、任务工时纳入营业日负荷、容量覆盖和超负荷警告，并包含 Asia/Shanghai 的 HTTP 端到端用例。

自动调度与升级覆盖：已验证到期计划仅生成一次、次日推进、月末短月夹取后恢复锚点，以及责任人/30 分钟店长/120 分钟上级管理员三级通知的幂等记录。运营看板的完成率、按时率和逾期清单已有固定样例测试。

## 3. 业务 UAT 剧本

### UAT-01 每日开店

- 总部模板为三家店生成任务。
- 店长改派给当天值班人员。
- 店员在手机完成清单、上传照片并提交。
- 店长通过，运营看板数字同步更新。

### UAT-02 返工

- 员工提交错误陈列照片。
- 店长填写原因并驳回。
- 员工看到原因、修正并重新提交。
- 审计页能看到两次提交及复核记录。

### UAT-03 人员超负荷

- 给容量 480 分钟的员工分配总计 520 分钟任务。
- 系统显示超负荷但允许有权限的店长确认。
- 调整给其他人员后负荷立即重新计算。

### UAT-04 逾期升级

- 测试任务超过截止时间。
- 责任人收到站内提醒。
- 模拟超过升级阈值后，只有所属店长收到通知。

### UAT-05 权限隔离

- 店员、店长、区域经理、总部运营和系统管理员分别登录。
- 按权限矩阵逐项验证列表、详情、附件、导出和统计。

## 5. 缺陷等级

| 级别 | 定义 | 响应目标 |
|---|---|---|
| P0 | 数据泄露、数据损坏、无法登录、核心流程整体不可用 | 立即处理，阻止上线 |
| P1 | 关键角色无法完成任务且无可接受替代方案 | 当日响应，版本发布前解决 |
| P2 | 局部功能错误或体验明显受损，有替代方案 | 排入当前或下一迭代 |
| P3 | 文案、轻微样式、低频建议 | Backlog 评估 |
